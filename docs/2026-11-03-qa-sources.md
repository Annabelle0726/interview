## 三个小练习

### 1. React 列表“加载更多”

对应 **n04**。先做按钮加载版本，再接底部观察器；用可控制延迟和失败的模拟接口验证。

- 快速连续触发时，同一查询的同一页最多只有一个在途请求。
- 失败后保留原游标，可以明确重试；成功后才推进。
- 最后一页停止加载，空列表、加载中与失败状态能区分。
- 切换搜索条件后，旧结果及旧请求结束回调都不影响新列表。
- 离开页面时清理观察器与相关请求。

### 2. AI 接口结果校验

对应 **n01**。使用模拟响应，准备正常数据、缺字段、错误类型和无效 JSON。

- 正常输入正确展示；其他输入有明确反馈，页面不崩溃。
- 失败后结束加载，保留原问题并允许受控重试。
- 能解释静态类型、JSON 解析、结构校验和业务规则的区别。
- 结构正确但引用不属于当前资料，也能识别为业务校验问题。

### 3. 三分钟真实故障复盘

对应 **n06**。选一个确实发生过的问题，按复现、证据、修改与验证组织。

- 能说明自己的判断和实际修改，指出 AI 或同事提供的帮助。
- 有复现步骤、关键证据、对应 diff 和验证结果。
- 说明尚未确认的内容、影响范围和下一步。
- 没有做过的事件续传、权限或并发方案，单独作为后续设计讨论。

这些是准备与验收任务，不表示本次已经额外实现了分页 Demo、接入 Zod 或完成事件回放后端。
