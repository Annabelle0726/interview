# Vibe Coding：本次功能的实际工作记录

本次目标：突出 Python 开发与 Vibe Coding，补充 Agent Skills、简历表达和工程方法，并让手册支持加粗重点与红色面试提醒。

## 规格与验收

- `**词句**` 在正文、追问和重点提示中显示为加粗；未闭合的标记保持原文。
- 用户编辑的内容继续按普通文本保存，不执行 HTML。
- 题目可提供一条红色“面试重点”；重点有文字标识，不只靠颜色区分。
- 现有笔记、备份与个人回答继续可用；新增 Vibe Coding 题可以搜索和进入学习路线。
- 桌面和手机都能阅读，没有横向溢出。

## 本次 TDD 小案例

目标行为是新增的强调文本显示，而非改写已有业务规则。

1. 在 `tests/emphasis.test.ts` 写出加粗显示、未闭合标记保留、用户输入 HTML 转义的预期。
2. 初始 `Emphasis` 只输出普通文本。运行测试失败，实际结果仍是 `用 **Python** 做后端`，预期结果是 `用 <strong>Python</strong> 做后端`。这次失败来自缺少目标行为。
3. 在 `src/Emphasis.ts` 增加有限的加粗标记解析，用 React `strong` 节点显示，继续保留默认文本转义。相同测试通过。
4. 收紧匹配规则，保留跨行标记的原文，并补充对应断言。整套测试再运行验证。

这是一项有实际红、绿记录的小功能实践。Belay 等历史项目的预算和进程测试另有源码证据；不根据它们最终通过就推断历史开发顺序。

## Agent 分工与人的检查点

- 专题内容 Agent：读取相关 Skills，起草 6 道 Vibe Coding 专题；只编辑 `src/data/vibe-coding.json`。
- 岗位审查 Agent：只读检查 JD 对应材料与高亮重点，不修改共享文件。
- 主任务：审查口述事实与结构，接入数据、强调显示和学习入口，合并后执行测试、构建与浏览器验证。

检查的重点包括：新安装的 Skills 与长期工具经验分开；Python 能力由 Bloom / Belay 的真实实现支持；Library 不包装成 Python 项目；测试、集成与真实页面检查分别承担自己的验证职责。

## 可展示材料

- `src/data/vibe-coding.json`：简历条目、派工方式、5 类 Skills、工程方法、协作与演示准备。
- `tests/emphasis.test.ts` 与 `src/Emphasis.ts`：本次小功能的行为与实现。
- `src/QuestionView.tsx`：加粗内容、红色重点和个人回答编辑入口。
- `docs/project-evidence.md`：Bloom、Belay、Library 的代码依据。
